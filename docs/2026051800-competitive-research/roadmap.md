# budn' 产品路线图建议

基于 2026-05-18 竞品调研结论和当前代码现状。

---

## 核心判断

budn' 的唯一不可替代价值是**选择→Agent 反馈循环**：用户在 3D 视口点击一个面/边/顶点，Agent 理解拓扑上下文并精确修改。这是 text-to-cad、Zoo、ChatToSTL 都做不到的。所有路线图决策应以"多快能让外部用户体验到这个循环"为北极星。

当前状态评估：
- **Agent 后端**：19 个工具、原子暂存、Plan/Agent 模式、Web 搜索——架构完备，但生成质量缺少结构化修复循环和工程默认值
- **Web 前端**：72 个文件覆盖 CadQuery viewer、选择、chat、workspace tree、inspector、export——核心骨架已搭建
- **CadQuery Runner**：独立 Python 子进程，输出拓扑 metadata + mesh，STEP/STL/3MF 导出——功能完整
- **缺失环节**：生成质量打磨、端到端体验验证、公开展示、基准测试、标准件

---

## Phase 0：Agent 生成质量打基 — 2 周

**目标**：让 Agent 在 text-to-cad 的 10 个基准上通过 7/10+，建立质量基线。

**依据**：如果 Agent 生成的零件质量不够，后面所有展示、推广、社区都是空话。这是纯后端工作，不阻塞前端。

| 任务 | 交付物 | 验证方式 |
|---|---|---|
| 在 system prompt 中添加失败分类体系 | 更新 `agent-system-prompt.md`，包含 6 类失败（语法/几何/倒角/比例/布尔/装配）和对应修复处方 | Agent 遇到倒角失败时自动缩小半径重试，而非报错停止 |
| 添加工程默认值 | system prompt 中编码：壁厚 2-3mm、倒角 1-3mm、M3/M4/M5 通孔 3.4/4.5/5.5mm、坐标约定 | 用户说"做个外壳"时不再因缺少壁厚信息而反复询问 |
| 添加自然语言简报提取 | system prompt 指导 Agent 在生成代码前先输出结构化 brief（尺寸/特征/假设/验证标准） | chat 记录中可见 brief，用户可以在 Agent 动手前修正假设 |
| 移植 text-to-cad 10 个基准为自动化评估 | `benchmarks/` 目录，每个基准有 prompt + 测试用例 + 评分脚本 | 跑一遍得到通过率基线，记录到 plan-result |

**Phase 0 不做的事**：
- 不改 CadQuery/build123d 选型（调研结论：继续 CadQuery）
- 不改工具 schema（现有 19 个工具已足够）
- 不改前端

---

## Phase 1：端到端体验验证 — 3 周

**目标**：一个外部观察者可以坐下来，从头到尾走完"描述需求 → 看到零件 → 点击一个面 → Agent 修改 → 导出 STEP"的完整循环，中间不卡壳。

**依据**：Web 前端骨架已搭建（72 个文件），但端到端体验可能存在断点（WASM 桥接、WebSocket 重连、选择→Ref→chat 的数据流、CadQuery 结果渲染的延迟和状态同步）。这个 Phase 不是写新功能，而是打通和打磨。

| 任务 | 交付物 | 验证方式 |
|---|---|---|
| 端到端冒烟测试 | 录屏或 Playwright 脚本，覆盖完整循环 | 从 `bun run dev` 到 STEP 下载，全程不出错 |
| 选择→Ref→Agent 数据流验证 | 确认 `cadquery-selection.ts` → protocol → Agent turn context 的完整链路 | 用户点击一个面，Agent 响应中包含正确的 `@face[...]` 上下文 |
| Plan 模式可视化 | Plan package 在 chat 中可视化为结构化展示（不只是纯文本） | 用户能看到计划的目标文件、受影响文件、导出目标 |
| Agent 工具调用可视化 | chat 中展示 `cadquery_dry_run` / `cadquery_execute` 的进度和结果 | 用户知道 Agent 在干什么，不是盯着一个空转的 loading |
| STEP 健康度展示 | 导出面板或 inspector 中显示：有效/无效、实体数、包围盒、特征数 | 用户一眼看出模型是否可用 |

**Phase 1 不做的事**：
- 不做公开部署
- 不做 landing page
- 不做标准件集成
- 不做装配爆炸图、测量工具等高级 viewer 功能

---

## Phase 2：首次公开展示 — 2 周

**目标**：让外部用户（不是你自己）能访问 budn'，体验核心循环，并产生可分享的内容。

**依据**：竞品调研发现 text-to-cad 在 3 天内获得 442 stars，靠的是"可以直接用的开源工具 + 可见的演示效果"。budn' 需要一个等价的"首次可见"时刻。但 budn' 不是开源技能包，是一个有产品形态的 Web 应用，所以展示方式不同。

| 任务 | 交付物 | 验证方式 |
|---|---|---|
| 着陆页 | 单页面：产品定位 + 核心循环 GIF/视频 + "试用"按钮 | 一个不认识 budn' 的人看完页面后能用一句话说出产品是什么 |
| 展示廊（Gallery）| 10-15 个预生成零件，每个配有 prompt + STEP + 3D 预览 + 源码 | 用户可以浏览、旋转查看、fork 并修改 |
| "5 分钟做出你的第一个外壳"教程 | 图文或视频教程，完整覆盖 Arduino/树莓派 外壳场景 | 一个从未用过 CAD 的软件工程师跟着做，5 分钟内拿到可打印的 STEP |
| 基准测试透明页 | 公开展示 text-to-cad 10 个基准 + budn' 自有基准的通过情况 | 每个基准有：prompt、预期结果、budn' 实际结果、通过/失败标记 |

**展示廊零件来源**：
- text-to-cad 基准中通过的部分（#1-#7 预期可通过）
- budn' 自有基准 B06（电子外壳）、B08（树莓派壳）、B10（Gridfinity）
- 2-3 个手动打磨的高质量消费电子零件

**Phase 2 不做的事**：
- 不做用户注册/认证（先用邀请链接或公开 demo 实例）
- 不做多用户/多 workspace
- 不做 SEO/广告投放

---

## Phase 3：生成质量第二跳 — 4 周

**目标**：将基准通过率从 Phase 0 的基线提升到 15/22+，并建立持续评估基础设施。

**依据**：Phase 2 公开后会收到真实用户的失败案例。这个 Phase 用数据驱动的方式改进生成质量，不是拍脑袋调 prompt。

| 任务 | 交付物 | 验证方式 |
|---|---|---|
| 完整 22 场景基准套件 | B01-B22 全部实现，含自动化评分（执行有效性、尺寸精度、特征完整性、拓扑质量） | CI 中可一键跑完全部基准并输出通过率 |
| 参数化差异测试 | 每个基准的至少一个维度变体（如 width 100→120），验证输出按比例变化 | 改一个数字后，IoU 在合理范围内变化（不是生成完全不同的形状） |
| VLM 评判器 | 独立 VLM（Claude/GPT-4o）按 rubric 评分每个基准的生成结果 | 评分与人工判断的一致率 >80% |
| 失败案例分析和修复 | 分析 Phase 2 收到的真实失败案例，识别系统性问题并修复 | 每个系统性问题修复后，相关基准从 fail 变 pass |
| build123d 对比评估 | 在全部 22 个基准上同时跑 CadQuery 和 build123d 目标，对比通过率和几何精度 | 数据报告，用于后续是否引入 build123d 的决策 |

---

## Phase 4：生态建设 — 6 周

**目标**：从"能用"走向"好用"——让用户不需要从零开始，能快速组合已有资源完成设计。

| 任务 | 交付物 | 验证方式 |
|---|---|---|
| 标准件目录集成 | 接入 step.parts API 或建立最小目录（M2-M8 螺丝/螺母、常用轴承、常用连接器） | Agent 被要求"加四个 M3 螺丝柱"时能拉取真实零件尺寸 |
| 工作空间模板 | 10+ 个可 fork 模板（电子外壳、3D 打印支架、齿轮机构、Arduino/Pi 项目） | 用户点击"从模板开始" → 立即有一个可修改的初始项目 |
| 切片软件集成 | 一键导出到 PrusaSlicer / OrcaSlicer 格式 | 从 budn' 到 G-code 只需一次点击 |
| 渐进式参考加载 | Agent 上下文从一次性全加载改为按任务触发的渐进引用 | token 使用量下降 30%+，长对话中 Agent 不因上下文溢出而降质 |

---

## Phase 5：增长 — 持续

**目标**：建立 budn' 在 AI CAD 领域的可信度和社区。

| 任务 | 依据 |
|---|---|
| 公开基准排行榜 | 用 BenchCAD 子集 + budn' 自有基准做持续评测，对标 frontier LLM 零样本和 text-to-cad |
| 社区展示分享 | 用户生成的零件可以一键分享为带 3D 预览的链接 |
| 开发者文档 | 工作空间协议、工具 schema、Runner 接口文档，让高级用户可以扩展 |
| build123d 双目标（条件触发） | 如果 Phase 3 数据显示 build123d 在 >60% 场景上优于 CadQuery，启动迁移 |

---

## 时间线总览

```
Phase 0 (2周)     Phase 1 (3周)     Phase 2 (2周)     Phase 3 (4周)       Phase 4 (6周)
Agent 质量 ──────→ 端到端打通 ──────→ 首次公开 ──────→ 质量第二跳 ──────→ 生态建设
                                                                          │
                                                                          ↓
                                                                     Phase 5 (持续)
                                                                       增长
```

预计从现在到首次公开展示：**7 周**（Phase 0 + 1 + 2）。这是最快路径。

---

## 关键决策点

1. **Phase 0 结束时**：如果 10 个基准只通过 <5 个，需要在进入 Phase 1 之前追加一轮系统性调试（可能多花 1-2 周），而不是带着低质量体验去验证前端。
2. **Phase 2 结束时**：根据外部用户反馈决定 Phase 3 的优先级排序——是失败案例修复优先还是新场景覆盖优先。
3. **Phase 3 的 build123d 数据出来后**：如果 build123d Pass@1 显著高于 CadQuery 且几何精度差距可接受，在 Phase 4 启动双目标支持；否则继续 CadQuery 单目标。

---

## 不做的事（至少到 Phase 5 之前）

- **不做多用户/认证系统**——MVP 是单用户本地或邀请制 demo
- **不做 Agent 对话历史云同步**——文件系统是 source of truth
- **不做实时协作**——单用户单 session
- **不做移动端**——桌面浏览器优先
- **不做 OpenSCAD 新功能**——已确认冻结
- **不做 FreeCAD/Fusion 360 集成**——架构不同，不是同赛道
- **不做付费功能**——先证明价值，再谈变现
