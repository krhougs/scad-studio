# Plan-00: scad-studio 最小可用版本

## 目标

创建一个 Rust 桌面应用，能够打开 OpenSCAD (.scad) 文件，调用 OpenSCAD CLI 生成 STL，在 wgpu 3D 视口中渲染网格，并在文件被外部修改时自动重新渲染。

## 技术架构

```
┌─────────────────────────────────────────────┐
│  winit 窗口                                  │
│  ┌───────────────────────────────────────┐   │
│  │ egui UI 层                            │   │
│  │  - 菜单栏（File > Open）              │   │
│  │  - 状态栏（文件名、渲染状态）          │   │
│  └───────────────────────────────────────┘   │
│  ┌───────────────────────────────────────┐   │
│  │ wgpu 3D 视口                          │   │
│  │  - 网格渲染（顶点+法线+光照）          │   │
│  │  - 轨道相机（旋转/缩放/平移）          │   │
│  └───────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
         │                    ▲
         │ 文件路径           │ STL 数据
         ▼                    │
┌─────────────┐    ┌──────────────────┐
│ notify      │    │ OpenSCAD CLI     │
│ 文件监控    │───>│ .scad → .stl     │
└─────────────┘    └──────────────────┘
```

## Phase 划分

### Phase 1: 项目骨架与窗口

**输入**: 无（从零开始）
**目标**: 创建 Rust 项目，winit 窗口能启动并显示 wgpu 清屏色，egui 能渲染基础 UI。

**步骤**:
1. `cargo init` 创建项目
2. 配置 `Cargo.toml`，添加所有依赖
3. 实现 `main.rs`：winit 事件循环 + wgpu surface 初始化
4. 集成 egui-winit 和 egui-wgpu，显示一个简单菜单栏
5. 实现窗口 resize 处理

**验收标准**:
- `cargo run` 能启动一个窗口，背景为深色清屏色
- 窗口顶部有 egui 菜单栏，包含 File > Open 菜单项
- 窗口可正常 resize 不崩溃

**保护**: 无前序 Phase

### Phase 2: STL 解析与 3D 渲染管线

**输入**: Phase 1 的窗口骨架
**目标**: 能加载一个 STL 文件并在 wgpu 视口中渲染为带光照的 3D 网格。

**步骤**:
1. 定义顶点格式（位置 + 法线）和 uniform buffer（MVP 矩阵 + 光照参数）
2. 编写 WGSL 着色器（顶点变换 + Blinn-Phong 光照）
3. 实现 STL 解析模块：读取 STL 文件 → 生成顶点和索引缓冲区
4. 实现渲染管线：创建 render pipeline、绑定顶点/索引/uniform buffer、执行 draw call
5. 实现固定相机视角验证渲染结果

**验收标准**:
- 能加载一个测试 STL 文件并渲染为带光照的 3D 模型
- 模型有明确的明暗面（Blinn-Phong 光照生效）
- 开启深度测试，无 Z-fighting

**保护**: Phase 1 的窗口和 egui 集成不被破坏

### Phase 3: 轨道相机控制

**输入**: Phase 2 的渲染管线
**目标**: 实现鼠标交互的轨道相机，支持旋转、缩放、平移。

**步骤**:
1. 实现 `OrbitalCamera` 结构体：存储目标点、距离、方位角、仰角
2. 鼠标左键拖拽 → 旋转（修改方位角/仰角）
3. 鼠标滚轮 → 缩放（修改距离）
4. 鼠标中键/右键拖拽 → 平移（修改目标点）
5. 根据相机参数计算 view matrix，更新 uniform buffer

**验收标准**:
- 左键拖拽模型旋转，操作流畅
- 滚轮缩放，有合理的最小/最大距离限制
- 中键拖拽平移视角
- 加载新模型时相机自动 fit 到模型包围盒

**保护**: Phase 2 的渲染管线和 Phase 1 的 UI 不被破坏

### Phase 4: OpenSCAD CLI 集成

**输入**: Phase 3 的完整渲染系统
**目标**: 通过文件对话框选择 .scad 文件，调用 OpenSCAD CLI 生成 STL，自动加载渲染。

**步骤**:
1. 实现 OpenSCAD CLI 调用模块：接收 .scad 路径 → 生成临时 STL → 返回路径
2. 处理 OpenSCAD 的平台特定路径自动检测（macOS/Linux/Windows）
3. 集成 rfd 文件对话框到 File > Open 菜单
4. 实现异步渲染流程：用户选择文件 → 调用 CLI → 解析 STL → 更新渲染
5. 在 egui 状态栏显示当前文件名和渲染状态（渲染中/完成/错误）

**验收标准**:
- 点击 File > Open 弹出系统文件对话框，可选择 .scad 文件
- 选择文件后自动调用 OpenSCAD CLI 生成 STL 并渲染
- CLI 报错时在 UI 中显示错误信息
- 状态栏正确显示文件名和当前状态

**保护**: Phase 1-3 的所有功能不被破坏

### Phase 5: 文件变更监控与自动刷新

**输入**: Phase 4 的完整管线
**目标**: 监控打开的 .scad 文件，外部修改后自动重新调用 CLI 并刷新渲染。

**步骤**:
1. 集成 notify crate，监控当前打开的 .scad 文件
2. 文件变更时触发去抖动（debounce 300ms），避免频繁调用 CLI
3. 去抖动结束后重新调用 OpenSCAD CLI → 解析 STL → 更新渲染
4. 切换文件时取消旧文件的监控，注册新文件
5. 处理 CLI 进程管理：新请求到来时终止正在运行的旧进程

**验收标准**:
- 在外部编辑器修改已打开的 .scad 文件并保存，预览自动刷新
- 快速连续保存只触发一次渲染（debounce 生效）
- 切换到新文件后旧文件的变更不再触发渲染
- 多次快速触发时不会出现进程堆积

**保护**: Phase 1-4 的所有功能不被破坏

│   ├── main.rs              # 入口：事件循环、窗口管理

## 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| egui-wgpu 集成复杂度 | 中 | egui 官方提供 wgpu 集成示例，可直接参考 |
| wgpu API 变更频繁 | 低 | 锁定具体版本 |
| OpenSCAD CLI 未安装 | 中 | 启动时检测，未找到时给出明确提示 |
| 大型 STL 渲染性能 | 低 | 最小可用版本暂不优化，后续可加索引缓冲区去重 |
| 跨平台文件监控差异 | 低 | notify crate 已处理跨平台差异 |
