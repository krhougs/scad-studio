## Phase 1: 建立回归测试

### 输入

- 当前根因分析：`MeshData::from_triangles` 仅复制面法线，不做共享顶点法线平滑。
- 目标文件：
  - `tests/mesh_tests.rs`
  - `src/mesh.rs`

### 要保护的前序目标 / 边界

- 不修改渲染器、shader、OpenSCAD 导出链路。
- 不改变已有 bounds、indices、颜色默认值测试的预期。

### 操作步骤

1. 在 `tests/mesh_tests.rs` 添加一个最小回归用例。
2. 用共享顶点的相邻三角形构造场景，要求共享顶点的法线应被平滑，而不是维持各自面法线。
3. 只运行该测试，确认在现有实现下失败，且失败原因与法线未平滑一致。

### 验收标准

- 新测试先失败，不是因为拼写、导入或环境错误。
- 失败信息能直接证明当前法线策略不满足预期。

## Phase 2: 在网格构建阶段计算平滑顶点法线

### 输入

- Phase 1 中已经失败的回归测试。
- 当前 `MeshData::from_triangles` 的顶点构建逻辑。

### 要保护的前序目标 / 边界

- 保护 Phase 1 的测试表达和定位价值，不得通过弱化断言来“修复”。
- 保持 `MeshData` 对外结构不变。
- 保持锐边边界，不为了隐藏斜面三角片而把所有边都做成光滑。

### 操作步骤

1. 在 `src/mesh.rs` 为共享位置的顶点建立法线聚合逻辑。
2. 使用角度阈值限制可参与平滑的相邻三角面，避免跨锐边混合。
3. 将计算得到的平滑法线写回输出顶点。
4. 只保留解决问题所需的最小辅助函数。

### 验收标准

- Phase 1 回归测试转绿。
- 现有 `tests/mesh_tests.rs` 其他测试仍然通过。
- 代码改动能明确解释为何会减少斜面上的三角片明暗分块。

## Phase 3: 回归验证与独立 review

### 输入

- 已完成实现的 diff。

### 要保护的前序目标 / 边界

- 不为了通过单个测试而破坏 STL/3MF 的基本导入行为。
- 不新增无关重构。

### 操作步骤

1. 运行与网格相关的测试集，确认本轮修改没有破坏已有行为。
2. 调用独立 subagent 做 review，提供阶段目标、完整计划和变更范围。
3. 根据 review 结果修正问题并重新回归。
4. 在结果文档记录完成情况、变更摘要和遗留风险。

### 验收标准

- 相关测试命令通过。
- review 没有遗留阻断项。
- `plan-00-result.md` 已记录本轮执行结果。
